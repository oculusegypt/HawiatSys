استلم المشروع **من آخر حالة وصل إليها الـAgent السابق بالضبط** ولا تبدأ من الصفر، ولا تعمل reset، ولا تلغِ أي تعديل سابق.

آخر Agent وصل إلى مرحلة متقدمة جدًا:

* تم إصلاح مشكلة `utm_source`.
* تم توحيد مسارات الـpublic URL الديناميكية.
* تم إصلاح canonical / `og:url` / JSON-LD URLs.
* تم تحسين prerender.
* تم تحسين تحميل Hero.
* تم جعل الصور غير الحرجة lazy.
* تمت إضافة/تحسين أبعاد الصور.
* تم بناء المشروع.
* تم تشغيل prerender.
* تم توليد sitemap.
* تم بناء Hostinger archive.
* SEO Gate نجح.
* PHP lint نجح.
* SQLite داخل الأرشيف تم فحصها.
* تم استخراج الأرشيف وفحصه مبدئيًا.

**لكن المهمة لم تُغلق بعد.**

آخر Agent توقف أثناء مرحلة التحقق النهائي، لذلك لا تعيد تنفيذ الإصلاحات من البداية؛ أكمل من الحالة الحالية وركّز على إثبات النتيجة وإصلاح أي مشكلة حقيقية متبقية.

# 1 — أهم مشكلة جديدة: FAVICON / GOOGLE SEARCH ICON

هناك مشكلة واضحة لاحظتها الآن:

**الموقع لديه favicon بالفعل، ولكن أيقونة الموقع لا تظهر في نتيجة بحث Google.**

هذه نقطة يجب التحقيق فيها بشكل مستقل وبعمق.

لا تفترض أن السبب هو عدم وجود favicon.

افحص فعليًا:

```text
index.html
<head>
favicon links
manifest
apple-touch-icon
icons
public assets
robots
.htaccess
PHP output
prerendered homepage
Hostinger archive
```

أريد منك تحديد:

### A

ما هو favicon المستخدم حاليًا بالضبط؟

مثلاً:

```html
<link rel="icon" ...>
```

وما هو:

* path
* filename
* extension
* MIME type
* dimensions
* format.

### B

هل الرابط:

```text
/favicon.ico
```

موجود فعليًا؟

وهل يعمل HTTP 200؟

### C

إذا كان الموقع يستخدم:

```text
/logo.webp
```

أو أي صورة أخرى كـ favicon:

تحقق هل هذا متوافق فعلًا مع متطلبات Google للـfavicon.

### D

افحص هل favicon:

* قابل للوصول بدون authentication.
* غير محجوب بواسطة robots.
* لا يمر عبر redirect غير ضروري.
* لا يعيد HTML بدل image.
* لا يحتوي MIME type خاطئ.
* موجود داخل Hostinger archive النهائي.
* موجود في production بعد البناء وليس فقط في source.

### E

افحص الحجم والأبعاد.

إذا كان هناك favicon صالح أصلًا، **لا تنشئ favicon جديدًا بدون داعٍ**.

إذا كان الموجود غير مناسب لـGoogle، استخدم **أيقونة الهوية الحالية نفسها** وأنشئ منها favicon production صحيح بدون تغيير هوية الموقع.

يجب ألا يتغير اللوجو نفسه.

# 7 — أثبت أن إصلاح Hero نجح

الـAgent السابق حاول جعل Hero image dynamic من قاعدة البيانات وpreload لها.

لا أريد افتراض أن هذا نجح.

أثبت:

```text
ما هي أول Hero slide؟
ما هو URL الحقيقي لها؟
هل هي LCP؟
هل تظهر في HTML الأولي؟
هل preload يشير إليها؟
هل preload URL = actual image URL؟
هل الصورة موجودة؟
هل حجمها مناسب؟
هل يتم تحميلها مرتين؟
هل React يعيد استبدالها بعد التحميل؟
```

خصوصًا افحص السيناريو:

```text
static prerender hero
        ↓
React hydration
        ↓
API /slides
        ↓
hero replacement
```

إذا كان هذا يسبب تحميل الصورة مرتين أو تغيير LCP، أصلح السبب.

# 8 — لا تجعل preload hardcoded

هذه نقطة مهمة جدًا.

المطلوب:

**Dynamic URL**

وليس:

```text
/preload /images/Taqi-hero1.webp
```

لمجرد أن هذه الصورة موجودة اليوم.

إذا كانت Hero تأتي من:

```text

```

فليكن مصدر الـpreload من نفس مصدر البيانات أو من آلية prerender الحالية.

إذا لم توجد Hero صالحة:

استخدم fallback الموجود فعليًا.

ولا تجعل fallback يشير إلى asset غير موجود.
