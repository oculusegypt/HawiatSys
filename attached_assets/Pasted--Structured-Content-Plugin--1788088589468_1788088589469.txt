أريد منك تنفيذ نظام داخلي داخل الموقع يحاكي وظيفة **Structured Content Plugin** بالكامل، ولكن **بدون تركيب أو الاعتماد على أي WordPress Plugin خارجي**.

الهدف هو إنشاء نظام Structured Content / Schema Markup أصلي داخل المشروع، بحيث أستطيع من لوحة الإدارة إنشاء وإدارة عناصر المحتوى المنظمة، ويتم إخراجها تلقائيًا في صفحات الموقع بصيغة **JSON-LD متوافقة مع schema.org**.

### المطلوب:

1. إنشاء نظام لإضافة Structured Content من لوحة الإدارة، مع دعم الأنواع المهمة مثل:

   * FAQPage
   * Article
   * LocalBusiness
   * Service
   * BreadcrumbList
   * WebPage
   * Organization
   * ImageObject
   * JobPosting
   * Product
   * Review / AggregateRating عند استيفاء الشروط
   * وأي Schema مناسب لطبيعة الصفحة.

2. بالنسبة للـFAQ تحديدًا:

   * إضافة عدد غير محدود من الأسئلة والأجوبة.
   * ترتيب الأسئلة بالسحب أو التحكم في ترتيبها.
   * إمكانية تفعيل/تعطيل FAQ لكل صفحة.
   * عرض FAQ للمستخدم بشكل HTML حقيقي داخل الصفحة.
   * توليد FAQPage JSON-LD تلقائيًا من نفس البيانات.
   * عدم إنشاء Schema لأسئلة غير موجودة فعليًا في محتوى الصفحة.

3. بناء **Schema Engine مركزي** داخل المشروع:

   * يجمع بيانات الصفحة.
   * يحدد الـSchema المناسب.
   * يولد JSON-LD نظيفًا.
   * يمنع تكرار نفس Schema.
   * يمنع تضارب البيانات بين أكثر من مصدر.
   * يدعم @id والعلاقات بين الكيانات عند الحاجة.
   * يدعم graph واحد `@graph` بدل إنشاء عشرات JSON-LD المنفصلة بدون داعٍ.

4. النظام يجب أن يكون **Dynamic**:

   * لا أريد كتابة JSON-LD يدويًا لكل صفحة.
   * عندما يتم إنشاء صفحة/خدمة/منطقة/مقال، يتم توليد Schema تلقائيًا من بياناتها.
   * عند تعديل البيانات، يتحدث Schema تلقائيًا.
   * عند حذف الصفحة، لا يبقى لها Schema في صفحات أخرى.

5. إنشاء Validation قبل إخراج الـSchema:

   * التحقق من الحقول المطلوبة.
   * منع القيم الفارغة أو الوهمية.
   * منع URLs غير صحيحة.
   * منع AggregateRating إذا لم توجد مراجعات حقيقية.
   * منع بيانات غير موجودة في الصفحة.
   * منع Schema المكرر.

6. **لا تستخدم Plugin خارجي ولا تعتمد على مكتبة WordPress لهذه الوظيفة.**
   نفذها كجزء أصلي من المشروع وبنفس الـarchitecture الحالية.

7. مهم جدًا:
   قبل التنفيذ افحص الـSEO الحالي بالكامل، خصوصًا:

   * جميع JSON-LD الموجودة حاليًا.
   * Schema الموجودة في Layout / Components / Pages.
   * Organization / LocalBusiness.
   * Breadcrumbs.
   * Service.
   * FAQ.
   * WebPage.
   * أي Schema يتم توليده من الـbackend أو الـfrontend.

   ثم قم بعمل **Single Source of Truth** للـStructured Data حتى لا ينتج النظام Schema مكررًا.

8. لا تحذف أي Schema أو SEO موجود حاليًا قبل فهم مصدره ووظيفته.
   المطلوب **دمج وتحسين** الموجود، وليس استبداله بشكل أعمى.

9. أريد أيضًا إضافة وضع Debug داخلي للمطور يوضح:

   * ما هي الـSchemas التي تم توليدها لكل URL.
   * مصدر كل Schema.
   * الحقول التي تم استخدامها.
   * أي Validation errors.
   * أي Schema تم منعه بسبب التكرار أو نقص البيانات.

10. بعد التنفيذ اختبر النظام على جميع أنواع الصفحات الموجودة بالموقع، وليس صفحة واحدة فقط، وتأكد أن:

* JSON-LD صالح.
* لا يوجد Duplicate Schema.
* لا يوجد تناقض بين بيانات الصفحة وStructured Data.
* لا يتم توليد Schema لنوع صفحة غير مناسب.
* جميع URLs تستخدم canonical الصحيح.
* البيانات المحلية وبيانات النشاط التجاري متسقة في جميع الصفحات.

### النتيجة المطلوبة

أريد نظامًا داخليًا يؤدي نفس الفكرة الأساسية لـ **Structured Content Plugin**: إدارة Structured Content من داخل النظام + تحويله تلقائيًا إلى JSON-LD Schema.org، ولكن يكون **أقوى ومتكاملًا مع SEO architecture الحالية للموقع** وبدون أي Plugin خارجي.

ولا تبدأ في كتابة الكود مباشرة.

أولًا افحص الـSEO/Schema architecture الحالية بالكامل، حدد ما هو موجود وما هو ناقص وما هو مكرر، ثم نفذ النظام فوق الموجود بدون تكسير أي شيء حالي.
