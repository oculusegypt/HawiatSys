6. لا تغيّر البيانات إلا إذا كان المصدر authoritative واضحًا.

إذا كان هناك repair مطلوب، يجب أن يكون:

> minimal + reversible + data-preserving


# 28. عند وجود خطأ

لا تتوقف وتكتب تقريرًا فقط.

إذا كان الخطأ قابلًا للإصلاح:

```text
diagnose
→ patch
→ test
→ verify
→ continue
```

إذا كان هناك ambiguity حقيقي يمنع تعديل البيانات:

> لا تخمن.

لكن لا تستخدم ambiguity كسبب لوقف بقية المهمة.

# 29. المطلوب في النهاية

لا ترسل تقريرًا ضخمًا عن كل شيء تم قراءته.

أرسل تقرير إغلاق مختصرًا ودقيقًا يحتوي:

### Changed

ما تم تغييره فعلًا.

### Verified

ما تم التحقق منه.

### Commands / Checks

الاختبارات الفعلية التي نجحت.

### Production Output

عدد الصفحات:

```text
prerender pages = X
sitemap URLs = Y
```

### SEO

```text
homepage title = PASS/FAIL
homepage description = PASS/FAIL
canonical = PASS/FAIL
H1 = PASS/FAIL
FAQ = PASS/FAIL
schema = PASS/FAIL
```

### Data

```text
old phone numbers = FOUND / CLEAN
legacy branding = FOUND / CLEAN
SQLite integrity = PASS/FAIL
```

### Rendering

```text
SEO content in raw HTML = PASS/FAIL
runtime DOM parity = PASS/FAIL
```

### Hostinger

```text
PHP package = PASS/FAIL
archive = PASS/FAIL
production artifacts = PASS/FAIL
```

# 30. أهم تعليمات الاستلام

أنت لا تبدأ مشروعًا جديدًا.

أنت تستلم مشروعًا في منتصف إصلاح.

**لا ترجع للخلف.**

**لا تعمل Audit من جديد.**

**لا تنشئ خطة جديدة.**

**لا تكرر التحليل السابق.**

**لا تثق بشكل أعمى في التعديلات الأخيرة.**

ابدأ من:

```text
CURRENT GIT DIFF
```

ثم:

```text
FIX LAST SYNTAX/TYPE ISSUES
→ VERIFY SEO GENERATOR
→ VERIFY ENTITY GRAPH
→ VERIFY CONTACT DATA
→ VERIFY SQLITE
→ VERIFY LEGACY CLEANUP
→ BUILD
→ PRERENDER
→ SITEMAP
→ SEO GATE
→ RAW HTML
→ RUNTIME DOM
→ HOSTINGER/PHP
→ FINAL VALIDATION
```

وأهم قاعدة:

> **لا تقل "تم الإصلاح" إلا إذا رأيت الدليل في output النهائي.**

إذا وجدت أن Agent السابق نفّذ تعديلًا خاطئًا، لا تتردد في إصلاحه، لكن لا ترجع إلى الحالة القديمة بالكامل ولا تستخدم reset/revert شامل.

**ابدأ الآن من `git status` و`git diff`، ولا تستهلك tokens في إعادة قراءة التقرير أو المشروع الذي سبق فحصه.**
