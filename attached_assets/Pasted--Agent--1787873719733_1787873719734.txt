أكمل العمل **مباشرة من آخر نقطة وصل إليها الـ Agent السابق في المشروع الحالي**. لا تبدأ من الصفر، ولا تعِد تصميم خطة جديدة، ولا تعمل Reset للتعديلات الموجودة.

آخر حالة موثقة للوكيل السابق:

* تم تحسين `ServiceCard.tsx` و`ServicesSection.tsx`.
* تم إزالة الاعتماد على مكتبة الأسعار الثابتة، وأصبحت بيانات الأسعار/الحاويات تعتمد على الـ API.
* تم تعديل `generate-sitemap.mjs`.
* تم تعديل ترتيب بناء Hostinger حتى يتم توليد sitemap قبل إدخالها في الأرشيف.
* تم تعديل `prerender.mjs` لمعالجة الصور الاحتياطية القديمة.
* تم تعديل `api-index.php` لإضافة/الحفاظ على صور sitemap الديناميكية.
* تم التحقق من PHP syntax.
* تم بناء Hostinger archive سابقًا بنجاح.
* تم اكتشاف ومناقشة مشكلة stale image references مثل:
  `service-apartments.jpg`
  و`logo.webp`.
* تم تعديل `prerender.mjs` مرة أخيرة لمعالجة بقايا `logo.webp`.
* **آخر تعديل تم على `prerender.mjs` ولم يتم بعد إثبات دورة Build → Prerender → Sitemap → Archive → SEO Gate كاملة بعد هذا التعديل.**

لذلك من هذه اللحظة اتبع هذا المسار فقط:

# المرحلة 1 — افحص الحالة الحالية

ابدأ بـ:

* `git status`
* `git diff`
* راجع آخر تعديلات `prerender.mjs`.
* راجع فقط الملفات التي تم تغييرها ضمن هذه المهمة.

لا تمسح أي تعديل سابق.

لا تستخدم `git reset --hard`.

لا تستبدل ملفات المشروع بنسخة قديمة.

إذا وجدت تعديلات غير مرتبطة بالمهمة، لا تلمسها.

---

# المرحلة 2 — تحقق من آخر Patch قبل البناء

راجع تحديدًا أن آخر تعديل في `prerender.mjs` الخاص بالصور لم ينتج عنه:

* undefined variables
* imports ناقصة
* duplicate declarations
* صور غير موجودة
* paths غير صحيحة
* URLs مطلقة خاطئة
* تغيير غير مقصود في HTML
* كسر للـ prerender.

ابحث عن جميع المراجع القديمة مثل:

* `service-apartments`
* `service-villas`
* `hero-debris`
* `logo.webp`
* `images/logo.webp`

ثم فرّق بين:

1. reference مقصود وموجود.
2. reference قديم/stale.
3. reference داخل source code يجب أن يبقى.
4. reference داخل generated output يجب ألا يبقى.

**لا تحذف اسم ملف لمجرد ظهوره في source إذا كان مستخدمًا كـ fallback صحيح. تحقق من وجوده أولًا.**

---

# المرحلة 3 — SEO الديناميكي

حافظ على الإصلاح الذي تم سابقًا للـ public URL.

ممنوع إضافة production domain hardcoded.

يجب أن يظل المصدر المركزي للـ URL ديناميكيًا، ويُستخدم في:

* canonical
* `og:url`
* sitemap
* JSON-LD
* absolute image URLs عند الحاجة.

في production يجب أن ينتج النطاق المهيأ:

`https://alsahmm.com`

لكن من configuration/settings وليس hardcoded.

لا تعيد تغيير architecture إذا كانت تعمل.

---

# المرحلة 4 — Homepage SEO

بعد البناء افحص source HTML الحقيقي للصفحة الرئيسية.

يجب أن يحتوي على:

* title
* meta description
* canonical واحد
* `og:title`
* `og:description`
* `og:url`
* `og:image`
* robots
* JSON-LD
* H1 واحد
* المحتوى الأساسي للصفحة
* الروابط الداخلية الأساسية.

المهم:

**افحص HTML المصدر قبل JavaScript، وليس DOM بعد hydration.**

---

# المرحلة 5 — H1

تحقق أن:

`homepage H1 count = 1`

وأن الـ H1:

* ظاهر.
* حقيقي.
* غير مخفي.
* ليس fake SEO content.
* موجود في prerendered HTML.

ثم تحقق أن إصلاح homepage لم يسبب H1 إضافيًا في:

* service pages
* area pages
* article pages.

---

# المرحلة 6 — الصور

هذه المرحلة مهمة جدًا لأن آخر Agent كان يعمل على هذه المشكلة.

افحص جميع الصور المستخدمة في:

* homepage
* service pages
* area pages
* article pages
* OG metadata
* sitemap images.

لكل image URL:

1. هل الملف موجود فعليًا؟
2. هل المسار صحيح؟
3. هل الملف موجود داخل `dist`؟
4. هل الملف موجود داخل Hostinger archive؟
5. هل URL النهائي قابل للوصول؟
6. هل هو production URL؟
7. هل هو API upload URL أم static asset URL؟
8. هل الـ sitemap يشير إلى نفس الصورة الصحيحة؟

لا تسمح بوجود references مثل:

`/images/service-apartments.jpg`

إذا كان الملف غير موجود.

ولا تستبدل صورة صحيحة بصورة أخرى لمجرد توحيد الأسماء.

**تحقق أولًا من المصدر الحقيقي للصورة.**

---

# المرحلة 7 — Sitemap

المشكلة السابقة كانت أن build كان ينسخ sitemap القديمة قبل توليد الجديدة.

تحقق الآن أن ترتيب التنفيذ النهائي هو:

**Generate sitemap → Build/copy final assets → Create Hostinger archive**

وليس العكس.

يجب أن يكون:

`public/sitemap.xml`

هو نفسه الموجود داخل:

`dist`

وهو نفسه الموجود داخل:

`Hostinger ZIP`

قارن hashes أو المحتوى إذا أمكن.

تحقق من:

* عدد URLs.
* عدم وجود duplicates.
* عدم وجود localhost.
* عدم وجود preview/staging domains.
* عدم وجود noindex pages.
* canonical consistency.
* الصور داخل sitemap صحيحة.
* image URLs لا تشير إلى ملفات غير موجودة.

# المرحلة 10 — SEO Gate

شغّل `seo-quality-gate.mjs` **بعد آخر build وprerender وsitemap وarchive**.

إذا فشل:

* لا تقل PASS.
* حدد السبب.
* أصلح أقل تغيير ممكن.
* أعد الدورة كاملة.

إذا كانت المشكلة Warning وليست Failure، لا تغيّر المشروع لمجرد إزالة warning ما لم يكن له أثر SEO حقيقي.

خصوصًا CTA warnings: لا تضف محتوى تجاري عشوائي فقط لإسكات الفحص.

# المرحلة 14 — الصورة التي ستظهر للمستخدم ومحركات البحث

في التقرير النهائي وضّح بدقة:

### Open Graph

ما قيمة:

`og:image`

وما اسم الملف ومساره.

### Google Search

لا تدّعي أن Google سيعرض OG image حتمًا.

وضّح أن Google قد يختار صورة من الصفحة وفق أنظمته، بينما `og:image` تتحكم أساسًا في Open Graph/social previews.

### Favicon

وضح ما هو الـ favicon/site icon إن كان مختلفًا.
