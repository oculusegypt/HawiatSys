# 🚨 FINAL OPERATIONAL E2E — لا تعتبر المهمة مكتملة

العمل الحالي جيد كبداية، لكن تقريرك يثبت **التعديل البرمجي فقط** وليس اكتمال الـOperational Domain.

أنا لا أريد منك الآن إضافة Features جديدة عشوائيًا، ولا أريد Migration للبيانات القديمة.

أريد منك **إكمال واختبار دورة التشغيل كاملة End-to-End** على البيانات المحلية فقط.

## أولًا — لا تكتفِ بالـBuild

نجاح:

* TypeScript
* PHP lint
* Build
* Health Check

لا يعني أن النظام يعمل.

المطلوب الآن اختبار حقيقي من:

**Contract → Container → Work Order → Assignment → Appointment → Execution → Completion**

# 4. Assignment

من أمر التشغيل:

> إسناد السائق

اختر الموظف/السائق الاختباري.

ثم تحقق:

```text

```

ولا يتم إنشاء Request جديد.

اختبر كذلك إعادة الإسناد إن كان النظام يسمح بها.

لا أريد Appointment منفصلًا بلا أصل تشغيلي.

# 6. دورة حالة التشغيل

وتأكد أن كل انتقال مسموح فقط وفق قواعد النظام.

# 7. Delivery

نفذ عملية:

```text

```

حتى `COMPLETED`.

ثم تحقق:

* Work Order أصبح Completed
* Appointment انعكس عليه التنفيذ
* الحاوية أصبحت بالحالة الصحيحة
* Assignment لم ينكسر
* Contract لم يتغير بشكل خاطئ
* لا يوجد Customer Request جديد
* لا يوجد Financial Transaction جديد

# 11. Idempotency

هذه نقطة إلزامية.

لكل عملية تشغيلية استخدم نفس:

```text
Idempotency-Key
```

مرتين.

مثال:

```text
OPERATIONAL-E2E-DELIVERY-001
```

المحاولة الأولى:

```text
201
```

المحاولة الثانية يجب أن تعيد:

```text
200
idempotent=true
same Work Order
```

ولا تنشئ Work Order ثاني.

اختبر ذلك على:

* Delivery
* Pickup
* Empty
* Return

إن كانت هذه العمليات تدعم الإنشاء عبر API.
