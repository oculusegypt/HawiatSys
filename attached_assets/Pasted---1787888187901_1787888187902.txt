كمّل من **آخر نقطة وصلت إليها تمامًا، ولا تبدأ من الصفر ولا تعيد أي تدقيق سابق**.

المهمة الآن محددة جدًا:

**إصلاح مشكلة التحليلات التي أرقامها لا تتحدث/تظل ثابتة، خصوصًا `page_views` و`active_visitors`.**

أنت وصلت بالفعل إلى:

* `analytics.ts`
* `Analytics.tsx`
* `visitorAttribution.ts`
* فحص `Cache-Control`
* موضوع `sqlite-active-visitors-integrity.md`

**استأنف من هنا مباشرة.**

نفّذ التالي بالترتيب:

1. أكمل قراءة الجزء الذي توقفت عنده في `analytics.ts` وحدد السبب الحقيقي لثبات الأرقام.
2. تتبع المسار كاملًا:
   **زيارة الصفحة → تسجيل `page_view` → heartbeat للزائر → API → SQLite → استعلام صفحة Analytics → تحديث الواجهة.**
3. لا تفترض أن المشكلة caching فقط؛ أثبت أين تنقطع البيانات.
4. أصلح السبب الفعلي في الكود، وليس مجرد إخفاء المشكلة أو وضع fallback بأرقام وهمية.
5. اختبر عمليًا:

   * إنشاء زيارة جديدة.
   * تسجيل `page_view`.
   * إنشاء/تحديث `active_visitor`.
   * heartbeat.
   * قراءة `/api/admin/analytics`.
   * التأكد أن الأرقام في صفحة Analytics تتغير فعلًا بعد النشاط الجديد.
6. **الإنتاج لا يدعم Node.** لا تقترح أو تعتمد على Node كحل إنتاجي. يجب أن يكون الإصلاح متوافقًا مع **PHP + SQLite على Hostinger**، مع الحفاظ على parity بين المصدر والنسخة PHP.
7. لا تغيّر نظام التحليلات إلى خدمة خارجية ولا تضف dependency غير ضرورية.
8. لا تمسح بيانات الإنتاج أثناء الاختبار. استخدم قاعدة مؤقتة/معزولة عند الحاجة.
9. بعد الإصلاح شغّل فقط الفحوص المرتبطة بالتغيير:

   * typecheck
   * tests ذات الصلة
   * PHP lint
   * build
   * اختبار نسخة Hostinger إذا تغيرت ملفات PHP.
10. إذا احتاجت نسخة Hostinger إعادة بناء، أعد بناء **`cleanflow-services-hostinger.zip`** وتحقق من الملف النهائي.

**ممنوع التوقف عند التحليل أو كتابة تقرير فقط.**
نفّذ الإصلاح كاملًا، اختبره، وأكمل حتى حالة نجاح نهائية.

ومهم جدًا:
**لا تعيد فحص SEO، ولا تعيد تنظيف الهوية القديمة، ولا تعيد مراجعة المشروع بالكامل؛ هذه الأعمال انتهت في الجولة السابقة.**
ركّز الآن على **Analytics / page_views / active_visitors / heartbeat / API / SQLite / PHP Hostinger** فقط.

إذا وجدت أن جزءًا من الإصلاح السابق غير صحيح، عدّله مباشرة بدل إنشاء حل بديل فوقه.

**الهدف النهائي:** عندما يتم فتح صفحة Analytics بعد وجود زيارات جديدة، تظهر الأرقام الحقيقية والمحدثة، وليس أرقامًا ثابتة أو بيانات قديمة بسبب cache أو state أو query أو heartbeat.
