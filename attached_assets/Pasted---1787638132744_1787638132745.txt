# 2. أهم اختبار: نوع العملية

يجب إثبات أن:

### Delivery

تؤدي إلى حالة التسليم الصحيحة.

### Pickup / Return

تؤدي إلى حالة الاسترجاع الصحيحة.

### Emptying

**لا يتم التعامل معها كـDelivery.**

يجب ألا يحدث أي انتقال خاطئ للعقد أو الحاوية نتيجة التفريغ.

أريد نتيجة صريحة لكل عملية:

```text
Operation
Work Order ID
Operation Type
Contract ID
Container ID
Initial Container State
Final Container State
Initial Contract State
Final Contract State
```

# 3. Requests vs Work Orders

هذه أهم نقطة في الإصلاح.

قبل الاختبار:

```text
service_requests = X
work_orders = Y
```

بعد إنشاء Delivery:

```text
service_requests = X
work_orders = Y + 1
```

بعد Retry لنفس العملية:

```text
service_requests = X
work_orders = Y + 1
```

ثم Pickup:

```text
service_requests = X
work_orders = Y + 2
```

ثم Emptying:

```text
service_requests = X
work_orders = Y + 3
```

**لا يجوز أن يزيد `service_requests` بسبب أي عملية تشغيلية.**

إذا زاد، أصلح السبب وأعد الاختبار.

# 4. Idempotency

اختبر كل عملية مرتين بنفس المفتاح:

```text
Delivery
Pickup
Emptying
```

ويجب أن يعود نفس `work_order_id`.

لا:

```text
new work order
new appointment
new assignment
```

عند إعادة نفس الطلب.

# 5. Driver Workflow

```text

→ Assigned
→ Accepted
→ Started
→ En Route
→ Arrived
→ Completed
```

لا تقم بتغيير الحالة مباشرة في DB.

# 6. Container / Contract Synchronization

هذا كان الـBug الحقيقي الذي اكتشفته.

لذلك يجب إثبات:

```text

→ Container/Contract synchronized correctly
```

و:

```text

→ Container/Contract synchronized correctly
```

و:

```text

→ Does NOT incorrectly perform Delivery synchronization
```

إذا وجدت اختلافًا، أصلحه ثم أعد الدورة كاملة.
