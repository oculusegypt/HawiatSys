### المطلوب

1. **Canonical**

   * حدد الـ1 صفحة التي بلا canonical وأصلحها من المصدر.
   * افحص الـ183 canonical الفعلية مقابل الـ166 Sitemap.
   * لا تحذف URLs من sitemap لمجرد جعل النسبة 100%.
   * لا تضف canonical وهمية.
   * كل صفحة indexable يجب أن يكون لها canonical صحيح ومطابق لمسارها الحقيقي.

2. **Sitemap ↔ Canonical Parity**

   * اعمل inventory كامل للـ315 HTML.
   * صنّف الملفات إلى:

     * indexable public HTML
     * prerender pages
     * duplicate/generated artifacts
     * application shells
     * admin/internal
     * assets أو ملفات لا ينبغي تحليلها كصفحات.
   * أصلح سبب وجود 183 canonical مقابل 166 sitemap.
   * يجب أن يكون الناتج النهائي متسقًا منطقيًا، وليس مجرد رفع الرقم إلى 100% باستثناء الصفحات.

3. **Meta Descriptions**

   * أصلح الصفحة الناقصة.
   * أصلح جودة الـ13 وصفًا خارج 120–160.
   * استخدم أوصافًا حقيقية مرتبطة بمحتوى كل صفحة.
   * ممنوع تكرار description واحد على عشرات الصفحات.
   * ممنوع حشو الكلمات المفتاحية فقط للوصول إلى عدد الحروف.

4. **Structured Data**

   * الـ28 صفحة التي لا تحتوي JSON-LD صالح يجب فحصها واحدة واحدة.
   * أضف Schema مناسبًا **حسب نوع الصفحة الحقيقي**.
   * لا تضف Schema عشوائيًا لمجرد رفع العداد.
   * حافظ على الأنواع الصحيحة الموجودة حاليًا مثل Organization / LocalBusiness / Service / Product / FAQPage / BreadcrumbList / Article وغيرها حيث تنطبق.
   * تحقق أن JSON-LD صالح فعليًا وقابل للتحليل.

5. **Internal Linking**

   * الـ28 صفحة الناقصة روابط داخلية يجب إصلاحها من محتوى الصفحة أو قالبها.
   * الروابط يجب أن تكون حقيقية ومفيدة للمستخدم ومرتبطة بالصفحة.
   * ممنوع إضافة روابط مخفية أو روابط dummy أو روابط متكررة فقط لإرضاء الـmetric.
   * تأكد أن صفحات الخدمات والمناطق والصفحات التجارية مترابطة منطقيًا.

6. **SEO Media**

   * افحص الـ24 ملف SEO المتوقعين واحدًا واحدًا.
   * حدد لماذا الـ12 غير مستخدمة.
   * إذا كانت أصولًا مطلوبة فعلًا، اربطها بالصفحات المناسبة من المصدر.
   * إذا كانت obsolete أو غير لازمة، أزلها من manifest/source بدل اعتبارها "مطلوبة".
   * لا تستخدم fallback عشوائيًا فقط لرفع النسبة.
   * لا تترك صورًا مكسورة أو references إلى ملفات غير موجودة.

7. **Legacy Branding**

   * FAIL بـ27 ملفًا يجب ألا يبقى.
   * ابحث في **المصدر + build output + generated artifacts + PHP + JS + HTML + metadata + service worker + build info + upload instructions**.
   * حدد كل إشارة قديمة قبل تعديلها.
   * أصلح الاسم/المعرفات القديمة من المصدر.
   * لا تستخدم global replace أعمى.
   * فرّق بين branding قديم فعلي وبين identifiers تقنية لازمة للتشغيل.
   * إذا كان الملف generated، أصلح generator وليس الملف الناتج فقط.
   * بعد ذلك أعد build كامل وتأكد أن الإشارات القديمة لا تعود.

8. **Site URL**
