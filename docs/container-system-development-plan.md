# خطة تطوير نظام إدارة الحاويات والأنقاض

## نتيجة المراجعة الحالية

النظام الحالي ليس نموذجًا شكليًا بالكامل؛ لديه لوحة إدارة، API، قاعدة بيانات، صلاحيات، سجل تدقيق، عقود، حركات، تحصيل، مصروفات، أسطول، تقارير وإعدادات. لكن الجزء الأكبر من الكيانات مخزن داخل سجل عام ببيانات JSON، ولذلك كان الخطر الأساسي هو إمكانية حفظ بيانات تبدو صحيحة في الشاشة دون أن تنتج حالة تشغيل موثوقة.

تمت معالجة أهم نقاط الخطر في المرحلة الحالية:

- رفض تسجيل حركة لحاوية غير موجودة أو بنوع حركة غير معروف.
- مزامنة حركة التسليم والاسترجاع مع حالة الأصل الفعلية.
- تحويل حالات الحاويات العربية إلى حالات تشغيل موحدة تعتمد عليها المؤشرات والتقارير.
- إيقاف الحركة غير الصحيحة وعدم تركها كسجل تشغيلي ظاهر عند فشل المزامنة.
- إعادة مزامنة لوحة المؤشرات بعد تنفيذ إجراء على العقد.
- إظهار نتيجة فشل مزامنة الحركة بدل إخفائها عن المستخدم.

## النموذج التشغيلي المستهدف

### 1. البيانات الرئيسية

- العملاء: أفراد، مؤسسات، الرقم الضريبي، حد ائتماني، عناوين ومواقع.
- أنواع الحاويات: التصنيف، السعة، الأبعاد، التسعير، شروط الاستخدام.
- أصول الحاويات: رقم أصل فريد، الحالة، الموقع، الفرع، الفحص، تاريخ الشراء والتكلفة.
- المركبات والسائقون والموظفون والفروع والمستودعات والخزائن.

### 2. دورة الطلب والتعاقد

`طلب عميل → تأهيل → عرض سعر → عقد/إيجار → حجز موعد → أمر تشغيل → تسليم → تبديل/تفريغ → استرجاع → تسوية وفاتورة → إغلاق`

كل انتقال يجب أن:

- يكون له حالة معروفة ومسموح بها.
- يسجل المستخدم والتاريخ والملاحظات.
- يتحقق من توفر الأصل والمركبة والسائق.
- ينتج الحركة أو المستند المالي المرتبط به.
- يظهر في سجل التدقيق ويمكن الرجوع إليه.

### 3. الحالات الرسمية للحاوية

`available → reserved → in_transit → rented → awaiting_return → in_transit → available`

والحالات الاستثنائية:

`inspection`, `maintenance`, `damaged`, `lost`, `out_of_service`.

لا يجوز أن تتغير حالة الأصل من نموذج عام دون حركة أو إجراء تشغيلي واضح، باستثناء إجراءات الصيانة والفحص والصلاحيات الإدارية.

### 4. المالية

- الفاتورة مرتبطة بعقد أو إيجار وبعميل.
- سند القبض مرتبط بفاتورة/عقد وخزينة وطريقة دفع.
- سند الصرف مرتبط ببند تكلفة وموظف أو مركبة أو أصل.
- قيد دفتر الأستاذ يولد من المستند المالي وليس من إدخال يدوي مكرر.
- كشف العميل يحسب: الإجمالي، الضريبة، المدفوع، المرتجع، والرصيد.
- لا يعتبر العقد مسددًا بمجرد إدخال إيصال غير مرتبط بعقد.

## تنظيم لوحة الإدارة

يجب أن تبقى الأقسام مجمعة حسب العمل وليس حسب أسماء الجداول:

1. **مركز التشغيل**: المؤشرات، التنبيهات، الخريطة، العمليات الحالية.
2. **العملاء والتعاقدات**: العملاء، عروض الأسعار، العقود، الإيجارات، الفواتير.
3. **الأسطول والحاويات**: أصول الحاويات، الأنواع، المواقع، الحركات، التفريغ والاسترجاع.
4. **المواعيد وأوامر العمل**: الجدولة، السائقون، المركبات، حالات التنفيذ.
5. **المالية والتحصيل**: سندات القبض، المصروفات، الإيداعات، الخزائن، مديونية العملاء.
6. **الموظفون والصلاحيات**: الموظفون، العمولات، الرواتب، الصلاحيات.
7. **المخزون والصيانة**: المستودعات، الأصناف، قطع الغيار، الصيانة، التصاريح.
8. **التقارير والتدقيق**: التقارير التشغيلية والمالية وسجل كل تغيير.
9. **الإعدادات**: المؤسسة، الضرائب، الترقيم، قواعد التشغيل والتنبيهات.

## مراحل التطوير المقترحة

### المرحلة الأولى — تثبيت الحقيقة التشغيلية

- اعتماد حالات موحدة ومصفوفة انتقالات.
- منع التكرار في أرقام الأصول والعقود والفواتير.
- ربط كل عقد بعميل وحاوية أو سبب واضح لعدم التخصيص.
- إضافة فحوص التوفر قبل التسليم والحجز.
- جعل الحركة المالية ومزامنة الأصل عملية واحدة قابلة للتراجع عند الفشل.

### المرحلة الثانية — تفكيك السجل العام

نقل الكيانات عالية الحساسية تدريجيًا إلى جداول واضحة:

- `customers`
- `container_assets`
- `contracts`
- `contract_lines`
- `container_movements`
- `invoices`
- `payments`
- `expenses`
- `work_orders`

يظل سجل JSON مفيدًا للإعدادات والحقول الإضافية، لكنه لا يكون مصدر الحقيقة للرصيد أو الحالة أو التوفر.

### المرحلة الثالثة — التشغيل الميداني

- أوامر عمل للسائق مع قبول وبدء وإنهاء ورفض مسبب.
- إحداثيات وصورة التسليم والاسترجاع.
- إثبات تسليم وتوقيع العميل.
- جدولة مسارات السائقين.
- تنبيهات التأخير والتداخل وانتهاء التصاريح والصيانة.

### المرحلة الرابعة — المالية والرقابة

- ترقيم مستندات غير قابل للتكرار.
- دفتر أستاذ قابل للمطابقة.
- إغلاق يومي للصندوق والخزائن.
- مرتجعات وإشعارات مدينة/دائنة.
- تقارير ربحية حسب العميل والعقد والحاوية والمركبة.

### المرحلة الخامسة — القياس والأتمتة

- تكلفة الرحلة ومعدل استغلال الأصل.
- عمر الحاوية وتكلفة الصيانة.
- نسبة التحصيل ومدة بقاء المديونية.
- ربحية العميل والمشروع.
- تنبيهات تلقائية وقواعد موافقات حسب المبلغ والصلاحية.

## معيار قبول النظام الحقيقي

يعتبر القسم جاهزًا تشغيليًا عندما يمكن تنفيذ السيناريو التالي من الواجهة دون إدخال يدوي مكرر:

1. إنشاء عميل.
2. إنشاء أو استقبال طلب.
3. إنشاء عقد مرتبط بالعميل والحاوية.
4. التحقق من توفر الحاوية.
5. تسجيل التسليم وتغيير الحالة.
6. تسجيل تبديل أو تفريغ.
7. تسجيل الاسترجاع وإعادة الأصل إلى المتاح.
8. إصدار الفاتورة وتسجيل القبض.
9. عرض كشف العميل وربحية العملية.
10. رؤية كل الانتقالات في سجل التدقيق.

ولا تقبل المرحلة أي شاشة تعرض رقمًا أو حالة لا يمكن تتبع مصدرها إلى سجل دائم أو مستند مرتبط.
