# المراجعة الشاملة وخطة تحسين تجربة المستخدم

**تاريخ المراجعة:** 22 أغسطس 2026  
**النطاق:** الموقع العام، لوحة الإدارة، العميل، السائق، الموظفون، الحاويات، العقود، أوامر العمل، التقارير، API، البيانات، الأمان، النشر والتشغيل.

**حالة التنفيذ الأخيرة:** أضيف مركز استثناءات التشغيل إلى لوحة القيادة، وحفظ طابور إجراءات السائق عند انقطاع الاتصال، وحفظ مسودة بيانات إثبات التنفيذ محليًا، وتصدير تقارير التحليلات بصيغة CSV والطباعة. أضيف كذلك فحص `pnpm --filter @workspace/scripts run validate:operational` لحدود الأمان والتكرار والتتبع العام.

## 1. الملخص التنفيذي

المشروع تجاوز مرحلة النموذج الشكلي: توجد واجهات فعلية، API، قاعدة بيانات، صلاحيات، دورة تشغيل للسائق، عقود وحركات حاويات، تحصيل، سجل تدقيق، SEO وتحليلات. أقوى أجزاء النظام حاليًا هي دورة أمر العمل الميداني، حماية التتبع العام، صلاحيات نظام الحاويات، وصفحات ملف العميل/الموظف/الأصل.

أهم المخاطر المتبقية ليست غياب الصفحات، بل:

1. اتساع لوحة الإدارة وكثرة الأقسام مما يزيد زمن الوصول للعملية المطلوبة.
2. اعتماد جزء من نظام الحاويات على سجل عام ببيانات JSON، مما يضعف التقارير والتحقق طويل المدى.
3. الحاجة إلى اختبار آلي يغطي الانتقالات المالية والتشغيلية.
4. الحاجة إلى مركز موحد للتنبيهات والاستثناءات بدل اكتشاف المشكلات من داخل الصفحات.
5. الحاجة إلى توحيد إدارة الملفات والنسخ الاحتياطي والمراقبة بين التطوير وHostinger.

## 2. مصفوفة الحالة

| المجال | الحالة | ما تم التحقق منه | الأولوية التالية |
|---|---|---|---|
| الموقع العام | جيد | مسارات خدمات وباقات ومدونة ومناطق وطلب وتتبع | قياس التحويل وتحسين الوصول والأداء |
| العميل | جيد | ملف عميل، مواقع، عقود، حاويات، مواعيد، أوامر عمل، تحصيلات | بحث موحد وسجل مالي أوضح وإجراءات أسرع |
| السائق | جيد | إسناد، قبول، بدء، وصول، إكمال، GPS، صورة، توقيع، ملاحظات | وضع ميداني أسرع، عمل عند ضعف الشبكة، قائمة استثناءات |
| الموظفون | جيد | إنشاء وتعديل وحذف وتفعيل وأدوار وصلاحيات مخصصة وفلاتر | سجل نشاط الموظف وتاريخ تغييرات الصلاحيات |
| الحاويات | جيد تشغيليًا | أصول، حالات، حركات، ملفات، عقود، صيانة، مالية وتدقيق | تفكيك الكيانات العامة إلى جداول مستقلة تدريجيًا |
| العقود | جيد | ربط العميل بالموقع والأصل، انتقالات، طباعة، مزامنة | قوالب وإصدارات واعتماد إلكتروني وتسويات آلية |
| التقارير | متوسط/جيد | تحليلات زيارات وتحويلات وفترات مخصصة وتصدير CSV وطباعة | تقارير تشغيل ومالية مجدولة مع تعريف واضح للمؤشرات |
| API | جيد | مسارات مستقلة للمجالات، تحقق وصلاحيات ومزامنة | توحيد الأخطاء، versioning، ومراقبة زمن الاستجابة |
| الأمان | جيد مع نقاط متابعة | صلاحيات الخادم، تقليل بيانات التتبع العام، تدقيق | فحص دوري، تدوير جلسات، وسياسة احتفاظ بالملفات |
| البيانات | متوسط | SQLite وDrizzle وبذور وترحيلات بدء التشغيل | نسخ احتياطية آلية، قيود وفهارس، وخطة ترحيل |
| Hostinger | جيد | PHP/SQLite مستقل وحزمة بناء | smoke checks بعد الرفع واسترجاع مجرب |

## 3. مراجعة تجربة المستخدم حسب الدور

### العميل وخدمة العملاء

**المسار المطلوب:** طلب سريع → تأكيد واضح → موعد → تتبع → إغلاق وتقييم.

التحسينات ذات الأثر الأعلى:

- إظهار ملخص الطلب والموعد والحالة في كل خطوة.
- حفظ سياق العميل عند فتح عقد أو دفعة أو موقع جديد.
- توحيد أسماء الحالة بين الموقع العام واللوحة.
- جعل الهاتف وواتساب والاتجاهات إجراءات مباشرة.
- إظهار الرصيد مع تفسير: إجمالي، مدفوع، مرتجع، مستحق.
- إضافة بحث عالمي بالاسم والهاتف ورقم العقد ورقم الأصل.

### السائق

**المسار المطلوب:** أعرف ما عليّ اليوم → أقبل → أتحرك → أصل → أثبت التنفيذ.

التحسينات:

- شاشة يومية افتراضية مرتبة حسب الموعد مع إبراز المتأخر والمتعارض.
- زر الإجراء الرئيسي واحد وواضح حسب الحالة الحالية.
- استمرار نموذج الإثبات عند فشل رفع الصورة مع عدم فقد البيانات.
- عرض الاتصال بالعميل والاتجاهات دون كشف بيانات مالية غير لازمة.
- تسجيل آخر مزامنة وحالة الشبكة عند إضافة وضع العمل غير المتصل.

### الموظف والمدير

- تجميع التنقل حسب العمل: مركز التشغيل، العملاء والعقود، الأسطول والحاويات، المالية، المحتوى، الإعدادات.
- إظهار الصلاحية الحالية وسبب منع الإجراء بدل إخفاء الزر فقط.
- سجل تدقيق مختصر داخل الملف، مع مقارنة قبل/بعد للتغييرات الحساسة.
- توحيد حالات التحميل والفراغ والخطأ وإضافة إعادة المحاولة.

## 4. خطة التطوير المرحلية

### المرحلة 0 — توحيد الأساس (1–2 أسبوع)

- اعتماد قاموس حالات موحد بالعربية والإنجليزية.
- توحيد رسائل API والأخطاء وحقول التواريخ والمبالغ.
- إضافة معرفات عملية و`Idempotency-Key` لكل العمليات المالية والحركية.
- تعريف مؤشرات التقارير: المصدر، الفترة، طريقة الاحتساب، وقت التحديث.
- إضافة سجل قرارات وتغيير صلاحيات الموظفين.

**معيار الخروج:** لا توجد شاشة تعرض حالة باسم مختلف عن API، وكل فشل قابل للإعادة دون إنشاء سجل مكرر.

### المرحلة 1 — مركز التشغيل (2–3 أسابيع)

- لوحة يومية للطلبات المتأخرة، تعارضات السائقين، الحاويات غير المتاحة، العقود المنتهية، والأرصدة المستحقة.
- فلاتر محفوظة حسب الدور.
- إجراءات جماعية آمنة مع تأكيد واضح.
- تحديث تلقائي مضبوط مع مؤشر آخر مزامنة.

**معيار الخروج:** يستطيع مسؤول الطلبات الوصول إلى أي طلب أو أمر عمل خلال أقل من 3 نقرات.

### المرحلة 2 — تجربة السائق الميدانية (2–3 أسابيع)

- واجهة ميدانية مبسطة للجوال.
- استعادة النموذج بعد انقطاع الشبكة.
- طابور رفع للصور والتوقيعات مع إعادة المحاولة.
- سجل زمني موثوق للأحداث.

**معيار الخروج:** إكمال مهمة كاملة من الجوال دون فقد بيانات عند انقطاع مؤقت للشبكة.

### المرحلة 3 — العملاء والعقود والمالية (3–5 أسابيع)

- بحث موحد وملف عميل كمدخل رئيسي.
- قوالب عقود وإصدارات ومراجعة قبل الاعتماد.
- ربط الفاتورة والإيصال والعقد والخزينة والدفتر.
- كشف حساب قابل للطباعة والتصدير.

**معيار الخروج:** كل دفعة مرتبطة بمستند، وكل رصيد قابل للتفسير من خلال حركاته.

### المرحلة 4 — البيانات والتقارير (2–4 أسابيع)

- تقارير تشغيلية ومالية منفصلة عن تحليلات التسويق.
- تصدير CSV/PDF وفق صلاحية المستخدم.
- تقارير دورية محفوظة وملخصات بريدية/إشعارات عند الاستثناء.
- تفكيك الكيانات الأكثر استخدامًا من JSON العام إلى جداول typed تدريجيًا.

**معيار الخروج:** يمكن إعادة بناء إجمالي التقرير من السجلات الخام مع فروق معلومة فقط.

### المرحلة 5 — الجودة والتوسع المستقر (مستمر)

- اختبارات API للصلاحيات والانتقالات والتكرار.
- اختبارات واجهة للمسارات الأساسية.
- مراقبة أخطاء وأزمنة API وحجم قاعدة البيانات والنسخ الاحتياطية.
- تجربة استعادة نسخة Hostinger في بيئة منفصلة.

## 5. مؤشرات قياس تجربة المستخدم

| المؤشر | الهدف الأولي |
|---|---:|
| زمن الوصول إلى طلب من لوحة الإدارة | ≤ 30 ثانية |
| إكمال أمر عمل للسائق دون مساعدة | ≥ 90% |
| فشل رفع إثبات التنفيذ دون استعادة | 0% |
| العمليات المكررة بسبب إعادة الإرسال | 0 |
| نجاح البحث بالاسم/الهاتف/رقم العقد | ≥ 95% |
| زمن تحميل الصفحة الأولى على الجوال | أقل من 3 ثوانٍ حيث تسمح الاستضافة |
| فروق التقرير المالي غير المفسرة | 0 |
| نجاح استعادة نسخة احتياطية | مرة واحدة على الأقل كل شهر |

## 6. قائمة التحقق قبل كل إصدار

### المنتج

- [ ] كل زر أساسي يوضح النتيجة بعد التنفيذ.
- [ ] حالات التحميل والفراغ والخطأ موجودة.
- [ ] الهاتف والجوال واتجاهات الخرائط تعمل من الجهاز المناسب.
- [ ] لا توجد بيانات تشغيلية حساسة في التتبع العام.

### التقنية

- [ ] `pnpm run typecheck`
- [ ] فحص API والصلاحيات والانتقالات.
- [ ] `pnpm --filter @workspace/scripts run validate:operational`
- [ ] تحديث codegen بعد أي تغيير OpenAPI.
- [ ] مراجعة سجل الخادم والمتصفح.
- [ ] نسخ احتياطي قبل تغييرات البيانات.

### Hostinger

- [ ] بناء أرشيف جديد.
- [ ] التأكد من وجود `index.html` و`api/` و`data/` و`uploads/`.
- [ ] اختبار تسجيل الدخول والطلب والتتبع والرفع.
- [ ] اختبار صلاحيات المجلدات وعدم إتاحة SQLite للمتصفح.
- [ ] تنفيذ خطة استرجاع معروفة قبل الإطلاق.

## 7. قرارات يجب عدم تغييرها دون مراجعة

1. لا تعتمد حماية الواجهة بدل فحص الخادم.
2. لا تُرجع تفاصيل السائق أو الإثباتات من مسار التتبع العام.
3. لا تعدّل حركة حاوية قديمة؛ استخدم حركة تصحيح موثقة.
4. لا تعتبر العقد مسددًا بمجرد وجود إيصال غير مرتبط.
5. لا تضف كيانًا جديدًا إلى السجل العام دون تحديد خطة فهارس وترحيل وتقارير.
