# مراجعة التقارير والإعدادات — CleanFlow

## الملخص التنفيذي

النظام يملك أساسًا تشغيليًا جيدًا: التتبع مجهول الهوية، التقارير تدعم فترات زمنية ومصادر وتحويلات وأجهزة ومواقع، والإعدادات موصولة مباشرة بالموقع العام. نقطة الضعف الأساسية ليست نقص البيانات، بل أن البيانات لا تتحول بما يكفي إلى قرار سريع، وأن الإعدادات تجمع مستويات تشغيل ومحتوى وهوية في مسار طويل.

## ما تم تطويره في هذه المرحلة

1. إضافة **ملخص القرار** أعلى صفحة التقارير، ويعرض القناة الأقوى، الصفحة الأكثر جذبًا، وقت الذروة، وجودة الطلبات اعتمادًا على بيانات الفترة الحالية.
2. إضافة **ملخص حالة الإعدادات** قبل التفاصيل: حالة استقبال الطلبات، الرابط العام، وعدد حسابات التواصل المكتملة.
3. الحفاظ على العقود الحالية وعدم إدخال بيانات وهمية أو خدمة خارجية.
4. توثيق التقييم وخارطة الطريق في هذا الملف لتكون مرجعًا للإصدارات القادمة.

## خارطة التطوير المقترحة

### المرحلة 1 — تحويل التقارير إلى مركز قرار

- مقارنة الفترة الحالية بالفترة السابقة مع مؤشرات صعود/هبوط.
- إضافة أهداف قابلة للضبط للزيارات والطلبات والتحويل.
- تعريف تنبيهات قابلة للتفسير: هبوط التحويل، ارتفاع الإلغاء، انقطاع التتبع، أو انخفاض الطلبات.
- إضافة فلاتر موحدة للمصدر والخدمة والمدينة مع حفظ آخر اختيار للمستخدم.

### المرحلة 2 — تقارير تشغيلية وربحية

- ربط الطلبات بمراحل زمنية: وقت الاستجابة، وقت التعيين، ووقت الإغلاق.
- تقرير أداء الخدمات والباقات، وليس الزيارات فقط.
- مؤشرات الفريق: الطلبات المسندة، الإنجاز، التأخير، وإعادة الجدولة.
- تصدير تقرير إداري منسق PDF/CSV مع ملخص تنفيذي وتاريخ إصدار واضح.

### المرحلة 3 — إعدادات آمنة ومفهومة

- تقسيم الإعدادات إلى: التشغيل، الهوية، المحتوى، الظهور، التكاملات، والصلاحيات.
- مؤشر «غير محفوظ» عند وجود تعديل، مع حفظ دفعة واحدة لكل قسم بدل الحفظ المتناثر.
- سجل تغييرات يعرض من عدّل ماذا ومتى، مع تراجع آمن للإعدادات القابلة للعكس.
- تحذير قبل تغييرات عالية الأثر مثل قفل الطلبات أو حذف بيانات التتبع.

### المرحلة 4 — جودة واعتمادية

- مراقبة صحة التتبع ووقت آخر حدث ناجح.
- سياسة احتفاظ بالتحليلات مع حذف انتقائي حسب الفترة بدل الحذف الكلي فقط.
- اختبارات عقود للحقول والحالات الفارغة، وفحص صلاحيات لكل مسار حساس.
- تحسين الاستعلامات عند نمو البيانات بدل تحميل كل الصفوف في الذاكرة.

## أولويات المنتج

الأولوية القصوى: **التحويل من قياس إلى قرار**، ثم **تقارير التشغيل والربحية**، ثم **سجل الإعدادات والتراجع**. هذه الأولويات تزيد قيمة النظام للمشرف يوميًا أكثر من إضافة رسوم جديدة فقط.
