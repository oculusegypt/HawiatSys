# نظام الحاويات — دليل التشغيل والأمان

هذا المستند هو المرجع المختصر للفريق عند تشغيل نظام الحاويات أو مراجعة صلاحياته.  
المصدر النهائي للتنفيذ هو الخادم وقاعدة البيانات، أما القوائم الجانبية في الواجهة فهي وسيلة تنقل فقط وليست حماية.

## حدود الوصول

جميع المسارات تحت `/api/admin/*` تتطلب جلسة إدارة صالحة وحسابًا غير مصنف كسائق. بعد ذلك يطبق نظام الحاويات صلاحية القسم على الخادم:

| المجال | الصلاحية |
|---|---|
| الملخص العام وقائمة السجلات | `container_system` |
| العملاء والمواقع | `container_system_customer` |
| الأصول وأنواع الحاويات | `container_system_container` أو `container_system_container_asset` |
| العقود ودورة العقد | `container_system_contract` |
| الحركات | `container_system_container_movement` |
| التسويات والتحصيل | `container_system_payment` أو `container_system_ledger_entry` |
| سجل التدقيق | `container_system_audit` |

حسابا `admin` و`manager` يملكان صلاحيات النظام الحالية. الحسابات الأخرى تعتمد على الصلاحيات المحفوظة بعد التحقق من أنها أسماء معروفة في قائمة الأقسام.

## دورة العقد المعتمدة

1. **إنشاء**: يجب أن يرتبط العقد بعميل، وموقع يتبع العميل، وأصل حاوية صالح.
2. **اعتماد**: يتم من حالة `draft` أو `pending_approval` أو `issued`، ولا يملك تنفيذه إلا المدير أو مدير النظام.
3. **تسليم**: مسموح من `active` أو `approved` أو `issued` أو `scheduled`، ويتطلب أن تكون الحاوية في حالة تسمح بالتسليم.
4. **استرجاع**: لا يبدأ إلا بعد حالة عقد `delivered`، وتتحقق الخدمة من أن الطلب المرتبط — إن وجد — يطابق أصل الحاوية.
5. **الحركات**: تُسجل كسجل جديد ولا تُعدل بعد إنشائها؛ التصحيح يكون بحركة موثقة جديدة.

كل انتقال ذري يحدّث العقد والأصل والحركة وسجل التدقيق ضمن معاملة واحدة. مفتاح `Idempotency-Key` يمنع إعادة إنشاء العملية نفسها عندما يدعمه المسار.

## بيانات التتبع العامة

مسار `/api/service-requests/:id` مخصص للتتبع العام، لذلك يعيد فقط:

- رقم الطلب واسم العميل ورقم الجوال.
- نوع الخدمة وحجم الحاوية.
- الحالة ونوع الموعد وتاريخه.
- تواريخ الإنشاء والتحديث.

لا يعيد هذا المسار الملاحظات الخاصة، توقيع المستلم، صور الإثبات، موقع السائق، أو تفاصيل الربط الداخلية. أي شاشة تشغيلية تحتاج هذه البيانات يجب أن تستخدم مسارًا إداريًا موثقًا.

## إدارة الموظفين

- الأدوار المقبولة هي: `admin`, `manager`, `customer_service`, `requests_officer`, `driver`.
- الصلاحيات يجب أن تكون من قائمة الأقسام المعتمدة فقط.
- المدير لا ينشئ أو يرقّي حسابًا إلى `admin`.
- لا يمكن للحساب إيقاف أو حذف نفسه.
- تغيير حالة الموظف يستخدم قيمة `0` أو `1` فقط، وتُحفظ في عمود `is_active`.

## قائمة مراجعة قبل النشر

- تحقق من أن كل مسار إداري يمر عبر `requireAdmin`.
- تحقق من وجود فحص صلاحية القسم لمسارات نظام الحاويات الجديدة.
- لا تضف حقولًا حساسة إلى استجابة التتبع العام دون مراجعة أمنية.
- لا تستخدم تعديل الحالة العام لتجاوز دورة العقد.
- افحص سجل التدقيق بعد أي تصحيح تشغيلي.
